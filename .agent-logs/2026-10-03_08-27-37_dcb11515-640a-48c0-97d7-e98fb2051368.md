## Keyset page module: agreed plan

**Interface** (`src/lib/keyset.ts`)

```ts
export const PAGE_SIZE = 24;

type KeysetSort = {
  key: string;                                   // goes into the cursor; "price-asc", "newest", ...
  value: SQL | Column;                           // the sort value
  id: Column;                                    // tie-break, same direction as the sort
  cast: "integer" | "numeric" | "float4" | "timestamptz";  // the cursor check is worked out from this
  direction: "ASC" | "DESC";
};

keysetPage(
  { sort, after?, before?, limit?, filters? },
  (page) => db.select({ ...fields, cursorValue: page.cursorValue })
              .from(...).where(page.where).orderBy(...page.orderBy).limit(page.limit),
): Promise<{ rows: T[]; nextCursor: string | null; prevCursor: string | null }>
```

**Inside the module:**
- Reading and writing cursors as `base64url([key, value, id])`. A cursor with the wrong key or a malformed value counts as page one.
- The limit: at most 24, at least 1.
- Fetching one extra row to tell whether another page follows.
- Flipping the comparison and order for `before`, then reversing the rows back.
- Deciding whether Next and Previous exist, with exactly today's behaviour.
- Getting the sort value as Postgres's own text, including the `::float8::text` workaround for ranks.

**Callers:**
- **`listProducts`** keeps its search logic, the `matched` CTE, its count query and `match`. Its sort table becomes five `KeysetSort` entries over `matched` columns, and its own cursor code is deleted.
